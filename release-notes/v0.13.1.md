# v0.13.1 — CI token safety and Python page tools

A security and bug-fix release from an audit of 0.13.0. Upgrade if you use
`load-report` with a CI run URL, or run the server against pytest-playwright
projects from npm, the `.mcpb` bundle or Docker.

## Security

- **`load-report` no longer sends your CI token to an untrusted host.** In
  0.13.0 the API address came from the host in the run URL, so a URL such as
  `https://example.net/o/r/actions/runs/1` (for instance one planted in a page,
  a log or a PR comment that the agent read) received `GITHUB_TOKEN` or
  `GITLAB_TOKEN`. The token now goes only to github.com, gitlab.com, the API
  set in `PW_MCP_GITHUB_API` / `PW_MCP_GITLAB_API`, or a GitHub Enterprise /
  self-managed GitLab host you list in the new `PW_MCP_CI_HOSTS` (comma
  separated). Other hosts are refused with a hint.
- **Tokens no longer follow redirects to other hosts.** Artifact downloads
  redirect to storage; fetch dropped `Authorization` there but kept GitLab's
  `PRIVATE-TOKEN` / `JOB-TOKEN`. Redirects are now followed by hand: every hop
  passes the address guard, and auth headers are sent only to the original
  API origin.

## Fixed

- **Page tools and `suggest-fix` work in pytest projects from a normal
  install.** They drive the browser with Node Playwright and fell back to one
  next to the server, which only existed in a repo checkout, so npm, `.mcpb`
  and Docker users got NO_PLAYWRIGHT. The server now depends on
  `playwright-core` (1.64.1, no bundled browsers). If the browser is missing,
  the error gives the exact command: `npx -y playwright@1.64.1 install chromium`.
- The Docker image can open pages with no project mounted, as its header
  promised.

## Tests and CI

- New tests for the token trust list and for redirects with a token attached.
- New CI job that installs the packed package without devDependencies and
  runs `inspect-page` from a pytest project; the Docker release checks a page
  tool inside the image before pushing.

Still twenty tools, Node 22 or newer.
