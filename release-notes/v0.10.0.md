# v0.10.0 — asks before changing files, interactive report, newer sign-in

Three steps from the MCP roadmap: the server asks before it writes, shows an
interactive test report in clients that support MCP Apps, and the hosted endpoint
accepts the sign-in method current MCP clients use. Still nineteen tools, Node 22
or newer, no new runtime dependencies.

## New

- **Ask before changing files.** `suggest-fix` with `apply`, `audit-tests` with
  `fix`, `generate-e2e-test` when it writes a spec, `quarantine` add/remove and
  `compare-visual-state` when it replaces a baseline now show the exact change
  (the diff, the new file, the entry) and ask first, when the client supports
  elicitation. A yes covers only that change. A no writes nothing and the result
  says `declined: true`. Works on the 2026-07-28 protocol (multi-round-trip) and
  on 2025 connections. `PW_MCP_CONFIRM_WRITES`: `auto` (default; ask when the
  client can, otherwise write as before), `always` (refuse writes in clients that
  can't ask), `off`.
- **Interactive test report (MCP Apps).** `run-test`, `get-run-status` and
  `get-failure` results come with a report view in Claude, ChatGPT, Cursor and
  other MCP Apps hosts: pass/fail counts and bar, a filterable failure list,
  expected vs. received, re-run one test or the whole run, and "Ask to fix". A
  background run updates when it finishes. The page loads nothing from the
  network and calls only this server's tools through your client. Other clients
  see no change. `PW_MCP_APPS=0` turns it off.
- **Client ID Metadata Documents on the HTTP bridge.** OAuth clients can use an
  https `client_id` that points at a small JSON document, the default in the MCP
  spec since 2025-11-25. The bridge fetches it over https only, without
  redirects, never from a private or reserved address, within 5 seconds and
  16 KB, and caches it for its `max-age`. Dynamic client registration keeps
  working for older clients. `PW_MCP_OAUTH_CIMD=0` turns it off.

## Upgrading

Nothing breaks. In clients that support elicitation you will now be asked before
files change; set `PW_MCP_CONFIRM_WRITES=off` to keep the old behaviour.

How to get 0.10.0:

- **`npx -y playwright-e2e-mcp`** (the README setup and what `init` writes):
  restart your MCP client; npx fetches 0.10.0 by itself.
- **Installed in the project:** `npm install -D playwright-e2e-mcp@latest`.
  **Globally:** `npm install -g playwright-e2e-mcp@latest`.
- **GitHub Action:** change `@v0.9.0` to `@v0.10.0` (the `version` input now
  defaults to 0.10.0).
- **Docker:** `docker pull ghcr.io/xsignon-secure/playwright-e2e-mcp:latest`.
- **Claude Desktop bundle:** download the new `.mcpb` below and open it.
- **Git clone:** `git pull && npm ci`.
- **Agent skill copied into a project:** run `npx -y playwright-e2e-mcp init`
  again.

`npx -y playwright-e2e-mcp doctor` says whether a newer version is out.
