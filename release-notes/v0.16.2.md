# v0.16.2 — History server journal and dependency fixes

A small release. Still twenty tools, Node 22 or newer. Nothing changes in the
MCP server's tools or the CLI.

## Fixed

- **The self-hosted history server no longer rewrites its whole file on every
  upload.** Each upload now appends one line to `history.jsonl`. The journal is
  folded into `history.json` on start and every 2,000 lines or 32 MB. Replay is
  safe to repeat and skips a half-written last line, so a crash mid-write loses
  nothing that was already saved. Large teams see much less disk writing.

## Changed

- **History server image on Node 26** (`node:26-alpine`, was 22).
- **README: setup for Windsurf, Cline and Zed**, each with its own config
  snippet (thanks to @YuuGR1337 for the first version in #46).

## Security

Dev-only dependencies; nothing in the published package changes.

- `node-forge` 1.4.3 (Dependabot alerts #18, #20, #21), used only to build and
  sign the `.mcpb` bundle.
- `minimatch` 11 and `glob` 14 under `c8`, the coverage tool (alert #17).
  Dependabot now ignores these two, since `overrides` already holds them on the
  fixed versions and its own update could not.

## Upgrading

`npx -y playwright-e2e-mcp@0.16.2`, or bump the version in your client config,
the GitHub Action (`xsignon-secure/E2E@v0.16.2`) or a CI template. If you host
the history server, rebuild its image; existing `history.json` files are read
as they are.
