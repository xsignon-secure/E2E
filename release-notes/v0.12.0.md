# v0.12.0 — tests that stay honest

Three ways a Playwright suite can be green while the app is broken, and what
this release does about each. Twenty tools now (new: `check-mocks`), Node 22 or
newer, no new runtime dependencies.

## New

- **Hydration races.** On server-rendered apps (Next.js, Nuxt, Remix, React
  Router, Gatsby, Astro, SvelteKit, Angular, Vue SSR) the HTML is clickable
  before JavaScript attaches its handlers, so a test can click, pass the step,
  and do nothing.
  - `inspect-page` names the framework and measures how long controls were on
    screen before the page hydrated, with the wait to add to the tests (a
    `html[data-hydrated]` marker set by a root effect, or `astro-island[ssr]`
    gone for Astro). A page that never hydrates within 5 s is reported.
  - `get-failure` flags a **possible hydration race** when a click or fill ran
    while the page's scripts were still downloading, before the step that
    failed, and lists hydration errors from the console. `diagnose-flaky` adds
    the same note when a failing run shows it.
  - `audit-tests` has a new `act-before-hydration` rule: a click or fill right
    after `goto` with nothing that waits in between, only in projects that
    depend on a server-rendering framework.
- **`check-mocks`: mocks that drifted from the API.** Finds every
  `route.fulfill` JSON body (TypeScript, JavaScript and pytest-playwright,
  inline or in a named handler, `json`, `JSON.stringify` or a `path` file) and
  every `routeFromHAR` recording, GETs each mocked endpoint on the live server,
  and compares JSON shapes: fields the mock relies on that the API no longer
  sends, changed types, new nulls, removed endpoints. Only GET requests are
  sent; write mocks, error mocks and wildcard routes without a mapping are
  listed as skipped. Tokens for the live calls come from `{{env:E2E_*}}`
  variables, never the chat. In CI: `npx -y playwright-e2e-mcp mocks
  --base-url https://staging.example.com` (exit 1 on drift).
- **Heal guard hardening.**
  - `assertion-made-conditional` (BLOCK): an assertion that always ran now sits
    inside an `if`, or after `&&` / `?`. A new conditional assertion next to
    the old ones is a WARN.
  - `early-return` (WARN): a `return` added before later assertions.
  - `runtime: true` runs each changed TS/JS spec in its old version (a
    temporary copy next to it, removed afterwards) and its new one, and counts
    the assertions each test actually executed. Fewer at run time is a BLOCK
    (`fewer-assertions-ran`), whatever the code looks like.
  - **pytest-playwright files** (`test_*.py`, `*_test.py`) are now guarded with
    the same rules: deleted `assert`s and `expect`s, `@pytest.mark.skip` /
    `xfail`, `pytest.skip()`, `try: … except: pass` around an assertion,
    weaker snake_case matchers, `wait_for_timeout`, `force=True`, raised
    `timeout=` and `reruns=`.

## Changed

- `check-test-change` is no longer annotated read-only, because `runtime: true`
  runs the tests. Clients that auto-approve read-only tools may now ask before
  calling it.
- All twenty tool definitions cost the model about 11,900 tokens per request
  (11,480 before); `core` is 2,323 (2,266).

## Upgrading

No breaking changes. How to get 0.12.0:

- **`npx -y playwright-e2e-mcp`** (the README setup and what `init` writes):
  restart your MCP client; npx fetches 0.12.0 by itself.
- **Installed in the project:** `npm install -D playwright-e2e-mcp@latest`.
  **Globally:** `npm install -g playwright-e2e-mcp@latest`.
- **GitHub Action:** change `@v0.11.0` to `@v0.12.0` (the `version` input now
  defaults to 0.12.0).
- **Docker:** `docker pull ghcr.io/xsignon-secure/playwright-e2e-mcp:latest`.
- **Claude Desktop bundle:** download the new `.mcpb` below and open it.
- **Git clone:** `git pull && npm ci`.
- **Agent skill copied into a project:** run `npx -y playwright-e2e-mcp init`
  again.

`npx -y playwright-e2e-mcp doctor` says whether a newer version is out.
